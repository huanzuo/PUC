三层次注释在路径中的位置：

[PUC\APP\项目A\{GUID_A}\MODULES\模块1]
├── __note__ = "这是模块1的配置节"           ← 节注释
├── DATABASE:数据库设置 = "mysql:3306" | "生产数据库"  ← 键注释 + 值注释
├── CACHE:缓存配置 = "redis:6379" | "缓存服务器"      ← 键注释 + 值注释
└── LOG_LEVEL = "INFO"                     ← 无注释（仅值）

路径深度示例：

Level 0: [PUC\STANDARD]
Level 1: [PUC\APP\]                     ← 一级域
Level 2: [PUC\APP\项目A\{GUID_A}]       ← 二级实例（必须带GUID）
Level 3: [PUC\APP\项目A\{GUID_A}\MODULES\]          ← 三级
Level 4: [PUC\APP\项目A\{GUID_A}\MODULES\模块1]     ← 四级
Level 5: [PUC\APP\项目A\{GUID_A}\MODULES\模块1\COMPONENTS\] ← 五级
Level 6: [PUC\APP\项目A\{GUID_A}\MODULES\模块1\COMPONENTS\组件1] ← 六级
... 可以继续深到 255 级（反斜杠分隔符限制）

*路径规则总结：*
1. 一级域：APP/TASK/DATA/LIB/NOTE/CONFIG/TEMPLATE/LOG
2. 二级实例：必须有自己的GUID {xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx}
3. 路径分隔：反斜杠 \ 作为层级分隔符
4. 注释层次：节(__note__) → 键(键名:注释) → 值(值 | 注释)
5. 元数据集成：每个二级节点建议包含 CREATED/UPDATED/AUTHOR/STATUS
